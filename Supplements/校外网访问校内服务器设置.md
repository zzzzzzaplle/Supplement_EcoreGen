# 校外网访问校内服务器设置

本文记录如何在校外通过 `wssocks-plugin-ustb` 访问校内服务器，并让 VS Code Remote-SSH 也走同一条校园网代理链路。

## 背景

`wssocks-plugin-ustb` 可以在本机启动一个面向校内资源的 SOCKS5 代理。浏览器插件 ZeroOmega 能访问校内网址，说明浏览器已经正确走了这个代理。

但 VS Code Remote-SSH 不会自动使用 ZeroOmega 的代理规则。要让 VS Code 连接校内服务器，需要让本机 SSH 客户端通过 SOCKS5 代理连接服务器。

## 关键判断

需要区分两个代理端口：

- 外网 VPN / Clash 端口：用于访问外网，例如 ChatGPT、GitHub。
- `wssocks-plugin-ustb` 端口：用于访问校内资源。

不要把校内服务器的 SSH 连接配置到外网 VPN 端口上。应使用 `wssocks-plugin-ustb` 的 SOCKS5 端口。

本次排查中：

- `127.0.0.1:33210` 属于外网代理，不适合访问校内服务器。
- `127.0.0.1:1080` 是 `wssocks-plugin-ustb` 出现后的本地监听端口，适合作为校内访问代理。

## 检查本地监听端口

在 PowerShell 中运行：

```powershell
Get-NetTCPConnection -LocalAddress 127.0.0.1 -State Listen |
  Select-Object LocalAddress,LocalPort,OwningProcess |
  Sort-Object LocalPort
```

确认 `127.0.0.1:1080` 是否正在监听。连接校内服务器前，需要保持 `wssocks-plugin-ustb` 已启动，并且 `1080` 端口存在。

## SSH 代理工具

Windows 上不一定需要安装 Nmap / `ncat.exe`。如果安装了 Git for Windows，可以直接使用它自带的：

```text
C:/Program Files/Git/mingw64/bin/connect.exe
```

该工具支持 SOCKS5 代理，可作为 SSH 的 `ProxyCommand`。

## SSH Config 配置

编辑：

```text
C:\Users\Zeqing\.ssh\config
```

示例配置：

```sshconfig
Host ustb-server1 ustb-server
    HostName 10.23.126.64
    User zhangzq
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ProxyCommand "C:/Program Files/Git/mingw64/bin/connect.exe" -S 127.0.0.1:1080 %h %p
    ServerAliveInterval 30
    ServerAliveCountMax 3

Host ustb-server-qwen
    HostName 115.25.45.126
    User zhangzq
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ProxyCommand "C:/Program Files/Git/mingw64/bin/connect.exe" -S 127.0.0.1:1080 %h %p
    ServerAliveInterval 30
    ServerAliveCountMax 3
    LocalForward 11434 127.0.0.1:11434
```

说明：

- `ustb-server1` 指向 `10.23.126.64`。
- `ustb-server-qwen` 指向 `115.25.45.126`。
- `ProxyCommand` 让 SSH 通过 `127.0.0.1:1080` 的 SOCKS5 代理访问服务器。
- `LocalForward 11434 127.0.0.1:11434` 用于把 qwen 服务器上的本地模型服务端口映射到本机。实际端口需要按服务器部署情况调整。

不要把服务器密码写入 SSH config。需要密码时，让 SSH 或 VS Code 交互式提示输入。

## 测试连接

先在 PowerShell 测试：

```powershell
ssh ustb-server1
```

或：

```powershell
ssh ustb-server-qwen
```

如果 PowerShell 可以连接，VS Code Remote-SSH 通常也可以连接。

## VS Code Remote-SSH 使用

1. 启动 `wssocks-plugin-ustb`。
2. 确认 `127.0.0.1:1080` 正在监听。
3. 打开 VS Code。
4. 使用 Remote-SSH 选择 `ustb-server1` 或 `ustb-server-qwen`。

VS Code 会读取 `C:\Users\User\.ssh\config`，并复用其中的 `ProxyCommand`。

## 常见问题

### 1080 没有出现

说明 `wssocks-plugin-ustb` 可能没有启动，或它使用了其他端口。先启动工具，再重新运行端口检查命令。

### 误用了 其他端口(比如我的vpn端口是33210)

`33210` 是外网 VPN / Clash 代理端口时，不适合访问校内服务器。SSH 应改回 `wssocks-plugin-ustb` 的端口，例如 `1080`。

### 浏览器能访问校内网站，但 VS Code 不能

浏览器能访问，通常是因为 ZeroOmega 配好了代理。VS Code Remote-SSH 不走 ZeroOmega，必须在 SSH config 中配置 `ProxyCommand`。
